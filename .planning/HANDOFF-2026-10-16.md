# Handoff — Trial-user conversion: results portal, share-for-discount, giveaway (2026-10-16)

Builds on `HANDOFF-2026-07-23.md` (infra, Coolify, migrations by hand). Mail is on **Mailgun**
(Resend was suspended in July), but campaign emails are **not sent by this app**: they are
sent from Sequenzy using CSVs and HTML templates produced here.

## What shipped

**Users / segments**
- Admin → Users: new filters (Trial: MT5 linked / not linked, running / ended) and an
  "Email lists" card with counts + CSV downloads (`GET /api/admin/segments/[segment]`,
  admin only). Rules live in `src/lib/segments.ts` (tested): staff, blocked, deleted,
  opted-out (`ReminderOptOut`), people who bought, test tiers and test addresses are never listed.
- CSV columns include `setup_link` (7-day magic link → guided setup), `tutorial_link`
  (magic link → link-MT5 video article), `portal_link` (private results link, 45 days).

**Results portal (secret link)** — `/results/submit?token=…` and dashboard **Rewards**
(`/dashboard/rewards`). Steps: link MT5 → send a screenshot → share it → reward code.
- Token: `src/lib/proof-token.ts` (JWT, purpose `results-portal`, `NEXTAUTH_SECRET`).
- Upload: `POST /api/proofs/upload`. Image is sniffed, re-encoded to WebP (EXIF removed),
  max 4 MB, de-duplicated by hash, stored privately at `proofs/<id>.webp`. Max 3 per person.
- Nothing is public until: person ticked consent + admin approved + admin pressed Publish.
- Images are only served by `GET /api/proofs/[id]/image` (admin: any; public: published
  only, and not from restricted countries).
- Admin: **Results & shares** (`/dashboard/admin/proofs`) approve/reject/publish; approving a
  shared post creates a single-use 25% code **bound to that person's email**
  (`Coupon.restrictedEmail`), emails it (`sendRewardCouponEmail`), and shows it in the portal.
- Checkout: `?coupon=CODE` prefills and opens the coupon box (applied after the email is typed,
  because the code is email-bound).

**Giveaway + list growth**
- Admin → **Giveaways**: create/edit (one live at a time), entries CSV, opted-in list CSV, draw.
- Public `/giveaway` (rules, countdown, form) and an exit-intent pop-up on public pages
  (`GiveawayPopup`, mounted in `[locale]/layout.tsx`). Entry = email + rules; email marketing
  is a **separate unticked box** and only then creates/updates `EmailSubscriber`
  (`source = giveaway:<slug>`). Approved proof / share each add one extra chance.
- Public `/results` wall of published screenshots (plus a link on the homepage).

**Tutorial video** — new `youtube` block type and article `link-mt5-account` embedding the
unlisted YouTube video `AC5MUEfv7eI` as a click-to-load `youtube-nocookie.com` player (no
YouTube request or cookie until play). `frame-src` in `next.config.ts` allows that domain.

**Reward pop-up** (`RewardsPopup`, mounted in `[locale]/layout.tsx`) — for signed-in people still
on their free trial: a launcher pill ("Earn 25% off, 2 of 3 done" with a progress ring), a
missions dialog (link MT5 → send results → share it) with the full upload/share form inside,
and a "Reward unlocked" card that opens once by itself when a code is earned. Hidden on
dashboard, checkout and login screens, hideable for 3 days. Data: `GET /api/rewards/summary`.

**Emails** — `marketing-assets/email-campaigns/`: `build.mjs` → 14 HTML templates in
`html/`, and `CAMPAIGNS.md` (which list gets which template, when, and the compliance rules).

## Compliance gate
The **country gate is off** (decision 2026-10-17): by default no country is blocked, so Pakistan
and India users are offered the reward, giveaway and pop-up like everyone else. To block
countries again, set `PROMO_BLOCKED_COUNTRIES` in Coolify (e.g. `PK,IN`); no redeploy of code is
needed beyond a restart. The **language gate stays on**: people browsing the Arabic, Hindi,
Bengali and Urdu sites are not offered promotions (`src/lib/promo-eligibility.ts`). Shared
posts must disclose the reward (the portal caption includes it); the admin page says to
reject posts that do not.

## Deploy checklist
1. Push (done by the push of this branch). Coolify rebuilds and redeploys on its own within
   minutes (confirm with `docker ps` that the image tag is the new commit).
2. **Run the migration as soon as the new container is up** (it is additive: new tables +
   `Coupon.restrictedEmail`): `docker exec <new app container> npx prisma migrate deploy`.
   Until it runs, anything touching the new tables or `Coupon` fails: the admin Users page,
   Giveaways/Results admin, the `/giveaway` and `/results` pages, and **coupon use at
   checkout** (the coupon query selects the new column). The pop-ups fail quietly. Everything
   else works. Keep the gap short.
3. Optional env: `PROMO_BLOCKED_COUNTRIES` (only if you want a country gate again).
4. Smoke test with throwaway rows (delete after): create a giveaway (Admin → Giveaways),
   enter it, open `/results/submit` from a CSV `portal_link`, upload a PNG, approve it,
   submit a post link, approve it, check the code arrives, the reward pop-up appears for that
   user, and the code applies at checkout for that email only.

## Top bar (added 2026-10-17)
`AnnouncementBar` (mounted in `[locale]/layout.tsx`) rotates every ~6.5 s between up to three kinds
of message, each with dots to pick one and a close button (hides for the browser session):
the live **giveaway** (title, prize, countdown, "Enter free"), the admin's **promo-bar messages**
(Admin → **Promo bar**; each can carry a public coupon code with a Copy button, a countdown and a
button to any page on the site), and the **rewards game** ("Share your results, get 25% off",
always on: "Play now" for signed-in people, "Try free" for visitors). Data comes from
`GET /api/promo/eligible`. A message about a coupon disappears by itself when the code is off,
expired or used up; free-licence codes and codes tied to one person can never be shown
(`couponShowable` in `src/lib/promo-banner.ts`, tested).
**New migration `20261019_promo_banner`** (one new table, nothing else touched). Until it runs the
bar still works: the API treats a missing table as "no messages". Run it the same way as before.

## Verified on the live site (2026-10-17, after the migration)
Smoke-tested against production with throwaway rows (all removed afterwards, including the
stored image): upload, duplicate and non-image refusal, private image until published then
served as WebP, results wall, share-link allowlist, one share per person, email-bound coupon
(right email works, others refused), giveaway entry (one per email, marketing list only when
opted in), public pages. **Not exercised** (need an admin login): the admin Approve/Reject/
Publish buttons (coupon creation and the reward email), Users-page filters/CSV downloads, the
draw, and the signed-in reward pop-up. Click through those once.
Found and fixed: the catalog no longer has a `goldbot` robot (now `precision-trader`,
`gold-multirange-4`), so reward links name no robot or plan: `/checkout?coupon=CODE`.
